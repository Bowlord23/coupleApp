# OurPlant

Одно растение для двух людей на расстоянии. Полейте его, коснитесь вместе,
оставьте несколько тёплых слов. Растение не умирает, не теряет очки и не требует
ежедневного внимания. Название меняется в `product.json`.

## Что уже сделано

- Expo / React Native приложение, в первую очередь для iPhone, также Android.
- Короткое знакомство, регистрация и повторный вход по коду из email.
- Восстановление сессии через SecureStore на телефоне.
- Создание пары, одноразовый код, максимум два человека и одна пара на аккаунт.
- Общее растение с шестью стадиями; полив, касание и совместный момент.
- Supabase Realtime Presence, приватные серверные события и синхронизация данных.
- Записка партнёру, последние 100 памятных событий, имена и настройки haptics.
- Выход, разъединение пары и удаление аккаунта с подтверждением.
- SQL-миграция, RLS, серверные ограничения и автоматические тесты.

**Статус:** рабочий Supabase подключён, миграция применена, а вход, создание пары
и соединение двух пользователей проверены на живом сервере. Приёмка всех сценариев
на двух физических телефонах ещё не выполнена. Это не обещание готового релиза
в Google Play или App Store.

Push пока не отправляется. Подготовлены библиотека, таблица токенов, клиентские
функции и план сервера в `supabase/functions/notify-partner/README.md`.
Финальные иконки/иллюстрации, Apple Sign-In, universal links и виджеты — позже.

## Стек

Expo SDK 57, React Native 0.86, React 19.2, TypeScript 6, Expo Router,
Supabase Auth/Postgres/Realtime, SecureStore, Haptics, SVG. Версии закреплены
в `package-lock.json`. Reanimated/Worklets установлены в совместимых версиях
для зависимостей Router; растение использует простой native-driver Animated.
Глобального state manager нет: один Context хранит серверное состояние.

SDK 57 требует Node.js не ниже 22.13 и iOS 16.4+. Рекомендуется Node.js 24 LTS.
См. [таблицу совместимости Expo](https://docs.expo.dev/versions/v57.0.0/).

## 1. Установка на компьютере

1. Установите Node.js 24 LTS с [nodejs.org](https://nodejs.org/).
   Node запускает инструменты разработки, npm устанавливает пакеты проекта.
2. Установите [Git](https://git-scm.com/downloads), если его ещё нет.
3. Откройте PowerShell и проверьте:

```powershell
node --version
npm.cmd --version
git --version
```

Получите проект:

```powershell
git clone https://github.com/Bowlord23/coupleApp.git
cd coupleApp
npm.cmd ci
```

`npm ci` устанавливает именно версии из lockfile. На macOS/Linux можно писать
`npm` вместо `npm.cmd`. Все дальнейшие команды выполняются **в папке coupleApp**.

## 2. Supabase уже подключён

Приложение подключено к рабочему проекту **OurPlant** в Supabase. URL и
publishable key встроены в клиент, поэтому после клонирования не нужно создавать
проект, выполнять SQL или заполнять `.env`. Публичный ключ можно безопасно
включать в мобильное приложение: доступ к данным ограничен RLS-политиками.

Локальный `.env` нужен только для запуска собственной копии бэкенда. Он
переопределяет встроенные значения:

```powershell
Copy-Item .env.example .env
notepad .env
```

```dotenv
EXPO_PUBLIC_SUPABASE_URL=https://ВАШ-ПРОЕКТ.supabase.co
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ
```

.env исключён из Git.
Не помещайте пароль базы, service role, Apple certificates или SMTP-пароль
в переменные с префиксом `EXPO_PUBLIC_`.

## 3. База данных

Миграция `supabase/migrations/20260905192934_initial.sql` уже применена к
проекту OurPlant. Созданы 8 публичных таблиц, на всех включён RLS; функции,
Realtime-публикация и политики приватных каналов также установлены.

Для отдельного нового Supabase-проекта:

1. В Supabase откройте **SQL Editor → New query**.
2. В репозитории откройте `supabase/migrations/20260905192934_initial.sql`.
3. Скопируйте весь файл в SQL Editor и нажмите Run **один раз**.
4. В Table Editor появятся `profiles`, `couples`, `couple_members`, `plants`,
   `plant_actions`, `notes`, `memories`, `push_tokens`. На всех включён RLS.

Миграция рассчитана на новый Supabase-проект. Не запускайте её поверх другой
рабочей базы с одноимёнными таблицами и не отключайте RLS для исправления ошибок.

Альтернатива через CLI (не нужна, если уже применили SQL вручную):

```powershell
npx supabase login
npx supabase link --project-ref ВАШ_PROJECT_REF
npx supabase db push
```

Project ref — часть URL до `.supabase.co`. При последующем переходе с ручного
SQL на CLI отметьте уже выполненную миграцию, чтобы не применить её повторно:

```powershell
npx supabase migration repair 20260905192934 --status applied
```

## 4. Вход по email и паролю

Регистрация и вход уже настроены и не требуют писем: пользователь вводит email,
придумывает пароль длиной от 8 символов и сразу получает сессию. Подтверждение
email отключено, потому что встроенный SMTP Supabase отправляет письма только
участникам организации. Благодаря этому оба партнёра могут зарегистрироваться
без отдельного почтового сервиса.

Для публичного релиза стоит подключить Custom SMTP, включить подтверждение email
и добавить восстановление пароля. Настройки почты и её секреты должны храниться
в Supabase, а не в мобильном приложении.

## 5. Realtime

Миграция добавляет таблицы растения, пары, участников, записок и моментов
в публикацию `supabase_realtime`. В Supabase Database → Replication / Publications
проверьте их наличие.

Публичный доступ к каналам уже отключён. Клиент использует `private: true`;
права на Presence и Broadcast проверяются политиками `realtime.messages`.
См. [Realtime Authorization](https://supabase.com/docs/guides/realtime/authorization).

Если Realtime недоступен, интерфейс перепроверяет сервер каждые 30 секунд
в активном приложении и после возврата сети. Это помогает восстановлению,
но не заменяет проверку мгновенных касаний на двух устройствах.

## 6. Установка на Android без Expo Go

Профиль `preview` создаёт обычный APK для прямой установки. После установки
приложение запускается самостоятельно: Expo Go и включённый компьютер не нужны.

```powershell
npx eas-cli build --platform android --profile preview
```

Откройте полученную EAS-ссылку на Android, скачайте APK и разрешите браузеру или
приложению «Файлы» устанавливать приложения из этого источника. Android может
показать предупреждение, потому что APK установлен напрямую, а не из Google Play.
Для обновления такой версии пока нужно установить новый APK поверх старого.

## 7. Запуск на iPhone

Expo Go — готовое приложение для запуска проекта во время разработки.
Установите совместимую с SDK 57 версию Expo Go из App Store. Телефон и компьютер
должны находиться в одной Wi-Fi сети.

```powershell
npm.cmd run start -- --go
```

Отсканируйте QR-код камерой iPhone и откройте его в Expo Go. На Android
откройте Expo Go и его сканер QR. Обычный `npm run start` тоже доступен;
из-за установленного `expo-dev-client` Expo может выбрать development build —
флаг `--go` явно выбирает Expo Go.

Если сеть блокирует соединение:

```powershell
npm.cmd run start -- --go --tunnel
```

Expo может предложить установку инструмента туннеля. После изменения `.env`
остановите сервер Ctrl+C и запустите:

```powershell
npm.cmd run start -- --go --clear
```

`npm run ios` открывает iOS Simulator **на Mac с Xcode**. На Windows используйте
физический iPhone через QR. `npm run android` открывает настроенный Android emulator.
Web-preview доступен через `npm run web`, но мобильный сценарий — основной,
а web-сессия намеренно не сохраняется на диск.

## 8. Проверка двух телефонов — обязательная приёмка P0

На обоих устройствах откройте один проект с одинаковыми `.env` и миграцией.
Не входите одним аккаунтом на двух телефонах для этой проверки.

1. Телефон A: войдите по коду для email A, задайте имя, создайте пространство.
2. Отправьте восьмизначный код партнёру кнопкой «Поделиться кодом».
3. Телефон B: войдите через другой email B, задайте имя, введите код.
4. A и B должны видеть одно имя растения. Код приглашения исчезнет.
5. Откройте Home на обоих: каждый видит, что партнёр здесь.
6. На A нажмите «Полить». На B должны обновиться состояние/реакция растения.
7. На A нажмите «Коснуться», на B ответьте в течение 10 секунд.
   Оба увидят «Вы здесь. Вместе.», а в истории появится совместный момент.
8. A оставляет записку — B видит её. Следующая записка заменяет предыдущую.
9. Повторный полив A в течение шести часов не должен начислить очки.
10. Сверните B: A должен перестать показывать B как online. Верните B.
11. Выключите интернет, попробуйте действие, верните сеть. Ошибки понятные,
    приложение не падает, данные восстанавливаются. Перезапустите приложение:
    вход должен сохраниться.
12. Аккаунт C не может вступить по старому коду или читать данные пары.
13. Проверьте разъединение и удаление аккаунта только на тестовых аккаунтах.

Факт успешной сборки не подтверждает эти пункты автоматически. До выполнения
этого списка P0 нельзя считать полностью принятым.

## Как устроены данные и безопасность

- Истина находится в PostgreSQL. Клиент не может записывать очки и членство
  напрямую. Все изменения идут через ограниченные RPC с `auth.uid()`.
- Создание/вступление блокируют нужные строки; primary key участника запрещает
  вторую активную пару. Приглашение генерирует сервер; после соединения оно удаляется.
- Неудачные попытки кодов ограничены сервером, в том числе после неверного кода.
- Полив: +5 очков, интервал 6 часов на человека. Касание: +1, интервал 3 секунды.
  Ответ второго человека за 10 секунд: +8, не чаще раза в минуту.
  Коэффициенты находятся в SQL `growth_config()` и `constants/product.ts`.
  SQL — источник истины; меняйте оба файла вместе и запускайте тесты.
- Полив и shared moments сохраняются; обычные касания не копятся в истории.
  Последнее касание нужно серверу для окна совместного момента.
- Повтор сетевого запроса с тем же UUID идемпотентен. Квитанции хранятся сутки;
  устаревшие очищаются при следующем действии растения.
- Presence не пишет в базу каждую секунду. `last_seen_at` — приблизительная
  последняя активность, не точное время закрытия приложения.
- Канал содержит UUID пары и версию. При уходе участника версия меняется,
  чтобы старый авторизованный сокет не получал новые события. Изменения таблиц
  дополнительно защищены RLS.
- Свой `profile` виден только самому пользователю; имя партнёра хранится отдельно
  в строке участника. Email партнёра не раскрывается.
- После разъединения оставшийся человек сохраняет растение/историю. Старый код
  не возобновляется. Для нового пространства нужно выйти из старого; повторное
  соединение той же пары не реализовано. Это явно указано в подтверждении.
- Удаление аккаунта удаляет auth user, profile, членство, его записки и токены.
  Общие моменты сохраняются у партнёра без ссылки на удалённого пользователя.

## Структура

```text
app/                   маршруты: Home, Моменты, Мы
components/            растение и базовые элементы интерфейса
constants/             тема и коэффициенты
features/auth/         вход и единый Context серверных данных
features/couple/       создание и приглашение
features/plant/        Home и правила роста
features/presence/     приватный канал, Presence, lifecycle
features/notes/        окно записки
hooks/                 haptics и обработка асинхронных действий
lib/                   Supabase и понятные ошибки
services/              загрузка пространства и подготовка push
types/                 типы сущностей и контракт базы
supabase/migrations/   схема, политики и серверная логика
tests/                 правила, настоящая SQL-миграция и RLS
```

Иллюстрации стадий находятся в `components/Plant.tsx`: SVG легко заменить,
сохранив входные свойства `stage`, `pulse`, `shared`. Цвета — в `constants/theme.ts`.
Иконки из Expo-шаблона пока временные. Бизнес-логика не зависит от картинок.

Типы можно пересоздать после изменения базы:

```powershell
npx supabase gen types typescript --project-id ВАШ_PROJECT_REF --schema public > types/generated.ts
```

Далее сверяйте generated contract с `types/database.ts`. Автоматическая подмена
файла с прикладными типами `Space` не нужна.

## Проверки и отладка

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run test
npm.cmd run test:db
npm.cmd run check
npx expo-doctor
npx expo export --platform all
```

SQL-тесты используют настоящий PostgreSQL-движок PGlite и полную миграцию.
Только Supabase Auth/Realtime infrastructure заменена минимальным стендом.
Проверяются RLS от роли authenticated, одноразовый invite, чужие запросы,
cooldown, идемпотентность, shared moment и удаление аккаунта. Это **не** тест
реального WebSocket, SMTP, SecureStore на iPhone или конкуренции разных
соединений PostgreSQL; эти проверки остаются в ручной приёмке.

GitHub Actions выполняет проверки и экспорт при push/PR. Экспорт создаёт JS
bundles и проверяет сборку Metro; он не создаёт подписанный `.ipa`/`.aab`.

Для отладки смотрите терминал Expo. В dev menu телефона доступны перезагрузка
и инструменты разработчика; клавиша `j` в терминале открывает React Native DevTools
для подключённого устройства. Ошибки авторизации смотрите в Supabase Auth Logs,
ошибки запросов — в API/Postgres Logs. Не публикуйте access tokens и содержимое `.env`.

Если в SDK-зависимостях появляются npm audit предупреждения, проверьте их
отдельно. Не запускайте `npm audit fix --force`: он может предложить старую,
несовместимую версию Expo. На момент подготовки есть умеренные transitive
предупреждения в инструментах Expo и обработчике URL; см. `docs/validation.md`.

## Development build и production

Development build — собственная версия приложения с нужными нативными модулями.
Нужна для настоящих push, Apple Sign-In и возможностей, которых нет в Expo Go.
EAS собирает iOS в облаке; Mac для облачной сборки не обязателен.

```powershell
npx eas-cli login
npx eas-cli init
npx eas-cli build --profile development --platform ios
npm.cmd run start -- --dev-client
```

EAS может потребовать Apple Developer account и регистрацию телефона. При
`eas init` сохраните созданный `extra.eas.projectId` в `app.config.ts`.
Для собственной копии бэкенда добавьте публичные Supabase URL и key в EAS
Environment Variables. Основной проект использует встроенную конфигурацию.

Для Android development build:

```powershell
npx eas-cli build --profile development --platform android
```

Перед production выберите постоянные bundle ID / package в `app.config.ts`,
замените временные иконки и выполните ручную приёмку. Затем:

```powershell
npx eas-cli build --profile production --platform ios
npx eas-cli build --profile production --platform android
```
