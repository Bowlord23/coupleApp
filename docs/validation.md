# Проверки и границы результата

Дата: 5 сентября 2026. Среда разработки: Windows, Node.js 24.

- TypeScript: проходит.
- ESLint: проходит.
- Unit tests: 6 проходят (рост, стадии, cooldown, shared window, invite,
  последовательное отключение/подключение Realtime и восстановление после ошибки).
- SQL: миграция выполняется в PGlite; 12 сценариев RLS/RPC проходят.
- Expo dependency check: совместимые версии, без конфликтов peer dependencies.
- Expo Doctor: 21 из 21 проверок.
- Metro export: успешно для iOS, Android и web.
- Браузер: проверены экран отсутствующей конфигурации, иллюстрация и переход
  onboarding → email; временный проверочный маршрут удалён из проекта.

Не проверено без внешней инфраструктуры:

- Применение миграции к аккаунту Supabase владельца.
- SMTP и настоящая регистрация двух email.
- Синхронизация, Presence, haptics, SecureStore, offline/reconnect на двух телефонах.
- Конкурентные SQL-запросы из разных PostgreSQL-соединений.
- Подписанная нативная EAS сборка и запуск её на iPhone/Android.
- Доставка push (сервер ещё не реализован), App Store review.

PGlite тестирует настоящие таблицы, ограничения, функции и политики приложения.
Он не запускает Supabase Realtime/Auth services. Не путать этот результат
с полностью принятой системой из двух физических устройств.

`npm audit` первоначально сообщает 13 moderate transitive findings:
`uuid` через `xcode` (инструменты сборки Expo) и `decode-uri-component` через
`query-string` (Router), включая цепочки зависимостей. Автоматическое исправление
предлагает несовместимый downgrade Expo/Router; оно не применялось.
Нет high/critical в этом отчёте. Перед релизом требуется обновление совместимых
upstream-зависимостей и повторная проверка; это не утверждение отсутствия рисков.
