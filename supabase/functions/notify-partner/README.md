# Push sender — P1, ещё не включён

В приложении есть Expo Notifications, конфигурация нативного плагина и
`services/notifications.ts` с регистрацией/удалением токенов. Таблица `push_tokens`
защищена RLS. Приложение **не запрашивает разрешение и не обещает доставку push**,
пока сервер отправки не развёрнут. Основной P0 работает через Realtime без push.

Будущая Edge Function `notify-partner` должна получать события о записке из
серверной очереди, а не доверять `recipient_id` или тексту из клиентского запроса.
План включения:

1. Добавить миграцию transactional outbox: получатель, note_id, версия записки,
   уникальный ключ доставки, статус, попытки и время следующей попытки.
2. Триггер `notes` добавляет событие только для текущего второго участника пары.
3. Worker с service role проверяет членство повторно непосредственно перед
   отправкой, учитывает online Presence/heartbeat, mute и лимит не чаще раза
   в 15 минут. Текст на экране блокировки — «Для вас оставили записку», без её содержания.
4. Отправить пакет в Expo Push Service; сохранить ticket ID, проверить receipts,
   удалить токены DeviceNotRegistered. Повторять только безопасные ошибки.
5. Доступ к worker закрыть серверным секретом/проверенным cron JWT.
   Service role хранится только в Supabase Edge Function secrets.
6. Включить явный переключатель в `app/us.tsx`, вызывающий `registerPushToken`
   и `disablePush`, и удалять токен устройства перед выходом из аккаунта.
7. Протестировать в development build на двух физических устройствах:
   foreground без лишнего push, background с push, mute, logout, повтор доставки,
   истёкший токен, разъединение пары и удаление аккаунта.

Доставка push не входит в проверенный P0. Не разворачивайте пустую функцию-заглушку.
Документация: https://docs.expo.dev/push-notifications/sending-notifications/
